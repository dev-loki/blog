wie ich arbeitehow I work

Ich fahre mehrere Werkzeuge parallel, prüfe jeden Treffer von Hand nach und setze daraus ein Bild zusammen. I run several tools in parallel, verify every hit by hand, and assemble one picture out of it.

Werkzeuge im Detail, read-only und reproduzierbarTools in detail, read-only and reproducible
  • Klassische statische Analyse.Classic static analysis. Linter, Komplexitätsmessung, Dependency- und Container-Scanner, je nach Stack. Etablierte Werkzeuge, deren Aussagen jemand anders nachprüfen kann.Linters, complexity metrics, dependency and container scanners, depending on the stack. Established tools whose output somebody else can check.
  • Git-Archäologie.Git archaeology. Wer hat was geschrieben, was ändert sich ständig, wo liegt Wissen fest. Das steht in keinem Linter-Report.Who wrote what, what churns constantly, where knowledge is stuck. No linter report shows that.
  • Handarbeit.Manual reading. Die kritischen Pfade lese ich selbst: Anmeldung, Rechteprüfung, Datenzugriff, Upload, Deployment. Genau dort sind Werkzeuge blind.I read the critical paths myself: login, permission checks, data access, upload, deployment. That is exactly where tools are blind.
  • Gegenprüfung.Cross-check. Ich lese die kritischen Pfade in zwei unabhängigen Durchgängen. Was sich widerspricht, kläre ich vor dem Report, nicht danach. Ein einzelner Durchgang übersieht am ehesten die Stellen, an denen man selbst am meisten Übung darin hat, wegzuschauen.I read the critical paths in two independent passes. Anything that disagrees gets resolved before the report goes out, not after. A single pass most often misses exactly the spots you have the most practice looking away from.
  • Gegenprobe.Adversarial check. Für Auth, Mandantentrennung, Zahlungen und Uploads reicht mir ein Lint-Fund nicht. Jeder Verdacht muss eine aktive Widerlegung überstehen, bevor er in den Report kommt. Was übrig bleibt, sind Logikfehler, die kein Linter sieht, zum Beispiel zwei Guard-Funktionen, die dieselbe Berechtigung unterschiedlich auslegen.For auth, tenant isolation, payments and uploads a lint finding is not enough for me. Every suspicion has to survive an active attempt to disprove it before it enters the report. What survives are logic bugs no linter sees, two guard functions, say, that interpret the same permission differently.
  • Architekturmethodik.Architecture method. Grenzen, Kopplung, Abhängigkeitsrichtung, Datenhoheit. Handwerk, keine Messung.Boundaries, coupling, dependency direction, data ownership. Craft, not measurement.
  • KI-Werkzeuge, optional.AI tooling, optional. Als Beschleuniger beim Lesen großer Codebases, nie als einzige Quelle, und nur mit deiner Freigabe. Jeder Fund landet erst im Report, nachdem ich ihn selbst im Code gesehen habe.As an accelerator for reading large codebases, never as the only source, and only with your sign-off. No finding enters the report before I have seen it in the code myself.

Ein Werkzeug allein liefert Zahlen, und Zahlen sortieren sich nicht selbst. Ein Lint-Befund wird erst wichtig, wenn er auf einem Pfad sitzt, der auch Rechte prüft. Eine langsame Abfrage wird erst dringend, wenn dieselbe Tabelle im nächsten Quartal das Zehnfache an Zeilen hat. Diese Verbindungen herzustellen ist die Arbeit, für die du mich bezahlst. Ein Linter findet Stil. Das hier soll den Satz finden: ein Nutzer kann auf die Daten eines anderen Mandanten zugreifen. One tool on its own produces numbers, and numbers do not sort themselves. A lint finding only matters once it sits on a path that also checks permissions. A slow query only becomes urgent once the same table holds ten times the rows next quarter. Making those connections is the work you are paying me for. A linter finds style. This is built to find the sentence: a user can read another tenant's data.

was danach läuftwhat runs afterwards

Ein Audit beschreibt den Stand an einem Tag. Ein generiertes Repo bekommt dieselbe Schwachstelle danach oft an zehn neuen Stellen, weil der Agent sie zehnmal nach demselben Muster schreibt. Deshalb liefere ich zusätzlich ein Harness, das die Checks aus diesem Audit regelmäßig selbst fährt, damit das nächste Mal nicht wieder bei null anfängt. An audit describes the state on one day. A generated repo often gets the same weak spot back in ten new places afterwards, because the agent writes it ten times from the same pattern. So I also deliver a harness that runs the checks from this audit on a schedule, by itself, so next time does not start from zero again.
